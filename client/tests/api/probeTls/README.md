# Local TLS / Qt-owned strict socket regression fixture

This standalone Windows QtTest fixture compiles the current mayakTunnelProbe.cpp with MAYAK_TUNNEL_PROBE_TESTING. It listens only on IPv4 loopback and connects by the hostname localhost. The test hook changes only endpoint/port and optionally delays connect; it does not bypass binding. The request uses the real IPv4 loopback interface. Qt creates and source-binds the TCP socket, then the same production Windows IP_UNICAST_IF path binds and verifies its interface. A second object target compiles the source without any test macro. Production unsupported platforms still fail closed.

Run from a compiler/SDK-configured shell (on Windows, an x64 Visual Studio developer prompt). Requirements: Python with cryptography, CMake, Ninja, and Qt 6.10.3 Core/Network/Test including a working SSL backend. Use a build directory outside the source inputs:

    python client/tests/api/probeTls/run-fixture.py --qt C:/Qt/6.10.3/msvc2022_64 --cmake cmake --ninja ninja --build-root C:/temp/mayak-probe-tests --report C:/temp/mayak-probe-tests/results.txt

The runner generates its CMake project under the selected build root, builds only local_tls_probe_tests, generates fresh local CA/server certificates inside a temporary child directory, runs the tests, and deletes that certificate directory on both success and failure. No CA private key is stored. No certificate/private-key file is a source input. Test CA trust is added to the Qt process configuration only and restored by RAII; system trust is unchanged. The fixture never calls ignoreSslErrors on the probe.

Network scenarios verify normal TLS close/duplicate remote-close notifications, exact honest User-Agent and percent-encoded nonce request, Content-Length/chunked/close-delimited framing, fragmented response, and a completely unread buffer drained at disconnected. Certificate trust/hostname, nonce/egress, HTTP 402, malformed/empty/truncated/oversized bodies fail closed. Deterministic signals after a complete network body verify that pending transport, fatal-alert, or certificate failures cannot turn into proof. Late server data after cancellation/deadline and cancellation before an already-queued retry cannot affect a replacement generation.

Fatal-error ordering is injected through Qt signals after a real TLS response; normal close, certificate errors, fragmentation and final-buffer cases use real local network events. Cancellation is posted through the event loop, matching the production bridge. Arbitrary synchronous cancel directly inside private child socket readyRead is not claimed safe; see the implementation evidence report for an observed reentrancy limitation.

The socket regressions assert retained descriptor/source port/address at TCP and TLS completion and compare the accepted server peer to the originally bound client port. A delayed-connect test holds the Qt-owned socket in BoundState and observes no early read notifications or socket warnings. Missing/mismatched interface inputs, replacement of the bound socket, and clearing the Windows interface option before connect or before GET fail without an HTTP request. Cancellation during the bound wait cannot start a connection. These checks do not prove Android VPN Network binding or cold device TLS behavior; those require a separate guest/device run.
